# Архитектура

Движок разбит на четыре модуля-сборки (asmdef). Границы держит компилятор:
`Dioma.Spikes` и `Dioma.Bio` физически не видят друг друга и ничего не знают
о мире; всё склеивает `Dioma.Body`.

```
        ┌──────────────────────────────────────────┐
        │  игра (Unity): сцена, спрайты, UI,       │
        │  геометрия мира, коллайдеры              │
        └───────────────┬──────────────────────────┘
                Sense   │   MotorAction
        ┌───────────────▼──────────────────────────┐
        │  Dioma.Body — существо                   │
        │  сенсоры → ток → мозг → тело → действие  │
        └───────┬───────────────────────┬──────────┘
                │                       │
    ┌───────────▼──────────┐  ┌─────────▼────────────┐
    │  Dioma.Spikes        │  │  Dioma.Bio           │
    │  LIF-alpha, STDP,    │  │  реакции крови,      │
    │  гомеостаз, награды  │  │  рецепторы, эмиттеры,│
    │  (не знает о химии)  │  │  орган (не знает     │
    │                      │  │  о спайках)          │
    └──────────────────────┘  └──────────────────────┘

    Dioma.World — только тестовая арена (`TestArena`) для тестов
    и headless-смоука; в игре не используется.
```

## Кто за что отвечает

**Spikes** — численное ядро. Вход: `float[] ext` (внешний ток на нейрон,
мВ за подшаг). Выход: суммы спайков моторных регионов за тик. Плюс дофамин
(`ScheduleReward`/`RewardNow`) и сон (`ClearEligibility`/`SleepConsolidate`).
Не знает, что означают его регионы — только теги в коннектоме.

**Bio** — метаболизм. Хост пишет драйв-локусы (`RateMotor`,
`GlucoseDeficit`) и события (`IngestFood`, `BumpWall`), зовёт `Update()`,
затем читает параметры тела: `SensorGain`, `MotorTonic`, `Speed`,
`TurnGain`, `WantsFood`, `PlasticityBudget`, `PayForPlasticity`. Внутри —
стехиометрические реакции, распад, рецепторы (химия → локус), эмиттеры
(локус → химия), орган «мозг» с ценой активности.

**Body** — единственное место, где спайки встречаются с химией:

```
Sense ─┬─→ ext = 0.12 + канал·SensorGain·CURRENT (по тегам регионов)
       │            ↓
       │        Brain.TickMotor → (ml, mr, spikes)
       │            ↓
       ├─→ RateMotor = ml + mr;  GlucoseDeficit = max(0, 150 − глюкоза)
       │   события (еда/удар) → Blood.Update()
       │            ↓
       └─→ MotorAction {
              Steer = clamp((mr − ml)·0.25·TurnGain, −1, 1)   ← МОЗГ
              Drive = clamp(MotorTonic / 0.5, 0, 1)           ← КРОВЬ
              Eat   = FoodNear && WantsFood()                 ← КРОВЬ
           }
```

Разделение принципиальное: **мозг рулит, кровь даёт тягу**. Голодный
рвётся вперёд и обостряет обоняние, сытый ленится, раненый едва ползёт,
стрессованный хуже учится. Без тела мозг молчит и никуда не идёт — это
проверено на практике: первая версия порта без `Bio` не съела ни одной
ягоды за 4000 тиков.

## Что делает игра

Игра реализует мир целиком: геометрия, коллайдеры, спрайты, спаун ягод.
От неё требуется одно — каждый тик (50 мс) заполнить `Sense` и применить
`MotorAction`:

```csharp
var sense = new Sense { SmellL = …, SmellR = …, FoodNear = …, WallHit = … };
var action = creature.Tick(sense);
if (action.Asleep) return;                  // существо спит
transform.Rotate(0, 0, action.Steer * turnPerTick);
transform.position += transform.up * (action.Drive * speed);
```

Ориентиры для сенсорики (формулы эталонной арены, `TestArena`):

| Канал | Формула |
|---|---|
| запах | `strength = 60/(60+d)`, разложение `strength·max(∓sin(rel), 0)` |
| зрение | `1 − d/40` в конусе ±75° |
| стена | `1 − d/8` по лучевым пробам шагом 1 |
| еда рядом | `d ≤ 2` |

Ключевая тонкость запаха: множитель `sin` делает его **градиентом**, а не
детектором. Прямо по курсу оба канала почти нулевые — существо различает
сторону, а не наличие еды. Так и должно быть: асимметрия каналов рождает
поворот, а симметрия означает «уже иду верно».

Стену стоит подавать только мозгам с регионами `WL`/`WR`. Лить её в
обоняние — ложный запах: существо поедет **в** стену (замерено: 974 удара
на 1000 тиков). Мозг без стенных регионов узнаёт о стене через боль удара
(`Sense.WallHit`) и учится отворачивать по отрицательному дофамину.

## Вычислитель мембраны: сменный кернел

Спайковая динамика — единственное место, где движок тратит время всерьёз
(десятки тысяч синапсов × 100 подшагов на тик), поэтому она вынесена за
интерфейс `ISpikeKernel`:

```csharp
// по умолчанию — SpikeKernels.Default (Managed)
var brain = DiomaBrain.FromJson(json);
// явно
var fast = DiomaBrain.FromJson(json, KernelMode.Fastest);
Debug.Log(fast.KernelName);   // «burst», если модуль установлен, иначе «managed»
```

| Режим | Что | Когда |
|---|---|---|
| `Managed` | обычный C#, эталон численного поведения | отладка, headless, чистый .NET |
| `Burst` | тот же алгоритм в нативном коде | арены с десятками существ |
| `Fastest` | Burst, если зарегистрирован, иначе Managed | продакшен |

Контракт узкий намеренно: кернел считает **только** мембрану и рассылку
спайков по CSR. Пластичность, гомеостаз, награды, сон и наследственность
остаются в `DiomaBrain` — они дешёвые (один проход по синапсам за тик против
ста проходов мембраны) и завязаны на семантику, которую незачем дублировать
в каждой реализации.

Тик отдаётся кернелу **целиком**: внутри тика веса константны (награды и
гомеостаз живут на границах тиков), поэтому кернел прогоняет все подшаги
подряд и возвращает историю спайков `steps × N`, а пластичность доигрывается
по ней в том же порядке. Для Burst это один переход в нативный код за тик
вместо ста.

`Dioma.Spikes.Burst` — отдельная сборка, которая регистрирует себя сама;
ядро о ней не знает. Билд без неё работает на `Managed`, просто медленнее.
Пакеты `com.unity.burst` и `com.unity.collections` подключает проект, не
движок — тогда `Dioma.Spikes` остаётся без зависимостей.

### Детерминизм и `FloatMode.Strict`

Burst по умолчанию волен переупорядочивать float-операции и сворачивать
mul+add в FMA. Здесь это недопустимо: рекуррентная кора хаотична, и сдвиг на
ulp через сотню тиков превращается в другое поведение. Поэтому job помечен
`FloatMode.Strict` + `FloatPrecision.High`, а тест `BurstMatchesManagedBitForBit`
гоняет 300 тиков и требует **нулевого** расхождения моторных сумм и весов.

Рассылка спайков по CSR не распараллеливается: это scatter с коллизиями (два
пресинапса пишут в один пост), а порядок сложений влияет на результат.
Детерминизм здесь дороже ещё одного ускорения — выигрыш даёт сам нативный
код и SIMD в шаге нейронов.

### Что показывает бенчмарк

На stage-C (760 нейронов, 32.5k синапсов), тик = 100 подшагов:

| | мембрана | пластичность | тик |
|---|---|---|---|
| Managed | 3.5 мс | 1.1 мс | 4.5 мс |
| Burst | 2.0 мс | 1.7 мс | 3.7 мс |

Мембрана ускоряется в 1.7 раза, тик целиком — в 1.2. Дальше упираемся не в
мембрану, а в mean-field STDP и разбор истории спайков (760 × 100 = 76 000
элементов за тик). Следующий шаг оптимизации — переносить в Burst
пластичность, а не искать ещё процентов в LIF.

## Паритет с Rust-эталоном

Движок — порт `dioma-engine` (Rust). Числа и порядок операций сохранены,
паритет держат тесты золотых следов, которые генерирует эталон:

| Экспортёр (в репозитории dioma) | Данные | Что проверяет |
|---|---|---|
| `export_connectome` | `dioma_*.json`, `dioma_c_*.json` | мозг: 240 тиков, моторные суммы точно |
| `export_bio` | `dioma_bio_golden.json` | биохимия: 600 тиков, все химии и локусы |

Мозг требует бит-в-бит совпадения арифметики (хаос рекуррентной коры
разносит ulp в расхождение поведения): `fast_exp` портирован не-fused,
`powi` — square-and-multiply, зеркала следов и рассылка спайков — через
`MathF.FusedMultiplyAdd`. Биохимия совпадает на 6e-8 относительной
погрешности — она числовая, без хаоса.
