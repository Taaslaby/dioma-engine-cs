# Руководство разработчика

## Рабочий процесс

Перед изменением:

1. Найдите владеющий модуль и существующий публичный контракт.
2. Проверьте asmdef-зависимости.
3. Найдите Rust-эталон или явно зафиксируйте, что его нет.
4. Определите единицы, порядок фаз и допустимые диапазоны.
5. Составьте минимальный тестовый сценарий.

После изменения:

```bash
# Быстрая компиляция harness
export PATH="$PATH:/c/Users/anton/.dotnet"
dotnet build Harness~/smoke.csproj -c Release

# Полный gate
scripts/verify.sh
```

## Изменение с численным паритетом

Если алгоритм уже имеет golden trace:

1. не меняйте эталон вручную;
2. найдите первую расходящуюся операцию;
3. сравните порядок вычислений, `float`/`double`, задержки и клампы;
4. исправьте порт или согласованно регенерируйте эталон из Rust;
5. проверьте все группы `parity`, `bio`, `skinner`, `arena`.

Если golden trace нет, добавьте инварианты. Для HAAP это покой, отсутствие спайков без тока, реакция на ток, адаптация к ступеньке и устойчивость при длительном прогоне.

## Шаблон нового stateful-компонента

Документируйте:

```text
Purpose: зачем компонент существует
Inputs: значения, единицы, допустимый диапазон
State: все изменяемые поля и раскладка памяти
Step order: точный порядок операций
Outputs: что возвращается и кто владеет буфером
Determinism: seed, random source, numeric requirements
Persistence: версия и поля снапшота
Failure modes: какие ошибки должны быть явными
```

## API и владение памятью

- Конструктор валидирует размер, объём и коэффициенты.
- `readonly` не заменяет защиту от изменения содержимого массива.
- Буферы горячего цикла переиспользуются и имеют одного владельца.
- `ReadOnlySpan` используйте для чтения без копирования.
- Событийные буферы очищайте между тиками.
- Индексы, полученные из имён, разрешайте один раз в `Bind`.
- `SubstanceId` нельзя передавать в `Blood` без `SubstanceMap`.

## Тестовая матрица

| Уровень | Что проверяет |
|---|---|
| Unit | формулы, границы и ошибки API |
| Integration | порядок Body → Spikes/Bio → Action |
| Replay | одинаковое продолжение из одного состояния |
| Golden | точный паритет с Rust |
| Smoke | сборка и полный сценарий без Unity |
| Performance | аллокации и стоимость горячего цикла |

## Диагностика расхождений

Сохраняйте минимальный воспроизводимый журнал:

- seed и версия формата;
- идентификатор коннектома;
- модель нейрона и kernel mode;
- номер тика и фаза;
- входной кадр;
- первое различившееся поле;
- значения до и после операции.

Сравнивайте сначала состояние, затем входы, потом порядок операций. Не начинайте с допуска: допуск может скрыть дрейф, который через сотни тиков станет изменением поведения.

## Definition of done

Изменение готово, если:

- контракт описан на русском и английском;
- тесты покрывают нормальный и граничный сценарии;
- состояние воспроизводится после снапшота;
- зависимости остаются направленными;
- нет новых скрытых аллокаций в горячем цикле;
- `dotnet build Harness~/smoke.csproj -c Release` проходит;
- `scripts/verify.sh` проходит;
- golden-файлы не редактировались вручную.
